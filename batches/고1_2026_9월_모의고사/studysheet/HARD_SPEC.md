# 고1 2026 9월 — 지문별 '가장 해석 까다로운 문장 1개 + 해석법' 스펙

대상: 담당 `passages/<파일>.json` 각각. 지문마다 **가장 해석이 까다로운 문장 1개**를 골라
`hard/<item_no>.json` 로 저장. (item_no 예: "20", "41-42")

## 고르는 기준(가장 까다로운 1문장)
단순히 긴 문장이 아니라 **구문 때문에 오역하기 쉬운** 문장 우선:
관계절 수식 방향, 삽입·도치, 생략(관계사/that/반복어구), 병렬, 상관어구(not only~but/the 비교급),
가주어-진주어, 부정·이중부정, 분사구문, 긴 주어·간접의문 등. grammar 칩 수·misreads·길이도 참고.

## 저장 형식 (hard/<item_no>.json)
{
  "item_no": "20",
  "sentence_id": 4,                 // 고른 문장 id(정수)
  "difficulty": "핵심 난점 한 줄 (예: 'you are not creating ~ ; you are creating ~' 대조 + 관계부사 in which)",
  "skeleton": "문장의 핵심 골격만 (주어+동사+목적/보어), 수식 걷어낸 형태",
  "steps": [                        // 해석하는 '순서'(3~5단계, 실전 팁)
    "1. 골격 찾기: 주어 __ / 동사 __ / (목적어·보어) __",
    "2. 수식·삽입·생략 처리: __ 는 __ 를 꾸밈 / __ 뒤 __ 생략 ...",
    "3. 어려운 구문 풀기: __(관계절/도치/병렬 등) 은 이렇게 ...",
    "4. 직독 → 자연스럽게: ..."
  ],
  "translation": "최종 자연스러운 해석(직역에 가깝되 말이 되게)"
}

## 규칙
- 한 지문당 정확히 1문장. sentence_id 는 그 지문 sentences[].id 중 하나.
- steps 는 '해석 방법'이 실제로 보이도록 — 골격→수식/생략→난구문→해석 순의 실전 절차.
- 원문/번역을 지어내지 말 것(문장은 그 지문 english 그대로, 해석은 정확하게).
- passages/*.json 원본은 수정하지 말 것. 오직 hard/ 에 새 파일만 생성.
- JSON 유효.
