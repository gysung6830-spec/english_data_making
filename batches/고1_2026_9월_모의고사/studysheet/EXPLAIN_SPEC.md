# 지문 이해하기 — 학생에게 설명하는 투 (explain/<item>.json)

각 지문 전체 내용을, **학생에게 말로 풀어 설명하듯** 따뜻한 구어체로 정리한다.
(문장 하나가 아니라 '지문 전체'를 다룬다. 지문 순서대로, 지문에 나온 단어로.)

## 출력: explain/<item>.json
```json
{
  "item_no": "20",
  "talk": [
    "이 글은 ~에 대한 이야기예요. 먼저 ...",
    "그런데 ...",
    "그래서 결국 글쓴이가 하고 싶은 말은 ...예요."
  ]
}
```

## 작성 기준
- `talk`: 2~4개의 짧은 문단(각 1~3문장). 이어서 읽으면 지문 한 편을 설명해 주는 느낌.
- **말투**: 학생에게 설명하는 구어체 존댓말("~예요/~해요/~죠", "먼저", "그런데", "그래서",
  "즉", "결국"). 딱딱한 개조식(‘~함, ~임’) 금지. 강의하듯 자연스럽게.
- **순서**: 지문 내용 흐름(도입→전개→주장/반전→결론) 그대로. overview.flow_blocks 의
  stage·summary·easy_example, topic/stance/structure 를 근거로 삼는다.
- **쉬운 설명**: 지문에 있는 핵심어(가능하면 한글로 풀되 필요하면 영어 병기)로 설명하고,
  flow_blocks 의 easy_example 같은 비유를 자연스럽게 녹여 이해를 돕는다.
- **정확성**: 지문에 없는 내용·통계·예시를 지어내지 말 것. 글의 주장과 반대로 요약하지 말 것.
- 분량: 전체 4~6문장 정도. 너무 길게 늘이지 말 것(가독성).

## 자기검증
- 지문 흐름 순서를 따르는가? 주장(stance)을 반대로 말하지 않았는가?
- 구어체 존댓말인가(개조식 아님)?
- JSON 유효, UTF-8(ensure_ascii=False).
