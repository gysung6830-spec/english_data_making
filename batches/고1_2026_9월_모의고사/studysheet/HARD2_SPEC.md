# 최고난도문장 해석법 v2 — 추가 분석 스펙 (hard2/<item>.json)

각 지문의 "가장 까다로운 문장"(hard/<item>.json 의 sentence_id)에 대해
아래 3가지 **판단이 필요한** 항목만 작성한다.
(직독직해·지문내용설명은 코드가 passage 의 chunks·flow_blocks 로 자동 생성하므로 작성 불필요.)

## 출력: hard2/<item>.json
```json
{
  "item_no": "20",
  "sentence_id": 4,
  "mistrans": {
    "span": "문장 영어에 '그대로' 있는 구절(한 조각)",
    "note": "왜 오역하기 쉬운지 + 올바른 해석 방향 (1~2문장, 간단히)"
  },
  "parallel": "동사 병렬구조에서 헷갈릴 수 있는 부분 설명. 없으면 null.",
  "prep_rel": "전치사+관계대명사가 있으면 해석법. 없으면 null."
}
```

## 작성 기준
1. **mistrans (오역 주의)** — 이 문장에서 **한글로 옮길 때 틀리기 쉬운 한 부분**을 고른다.
   - `span`: 그 부분의 영어 원문 조각. 반드시 문장 english 에 그대로 존재해야 함(형광펜 대상).
     문장에 2번 이상 나오는 짧은 단어는 피하고, 앞뒤를 포함해 **문장에서 유일하게** 잡히도록.
   - `note`: "이렇게 읽으면 틀린다 → 이렇게 읽어야 한다" 를 간단히. 과하게 길지 않게(1~2문장).
   - 근거: passage 의 misreads(특히 verdict=="X" 의 anchor·why)·mistips 를 활용하되,
     **comprehension trap 이 아니라 '번역(해석) 오류'** 관점으로 쓸 것.
   - 모든 지문에 반드시 1개 작성.

2. **parallel (동사 병렬구조)** — 등위접속사(and/or/but)·세미콜론 등으로
   **동사(구)가 병렬**되어 범위·연결을 헷갈릴 수 있으면 짚는다.
   - 무엇과 무엇이 병렬인지, 어디까지가 한 덩어리인지, 오해하면 어떻게 틀리는지.
   - 해당 문장에 헷갈릴 동사 병렬구조가 **없으면 null**(억지로 만들지 말 것).

3. **prep_rel (전치사+관계대명사)** — in which / by which / for which / of which /
   전치사+whom 등이 있으면 **어떻게 해석하면 좋은지** 설명한다.
   - 전치사+관계대명사 = "전치사 + 선행사" 로 풀어 읽는 요령
     (예: in which = in + 선행사 → '그 ~ 안에서'), 선행사가 무엇인지 명시.
   - 없으면 **null**.

## 자기검증 (제출 전 필수)
- `span` 이 해당 문장 english 에 그대로 있는가? (대소문자 무시, 부분문자열)
- `span` 이 문장에서 1번만 잡히는가? (여러 번이면 앞뒤 단어 포함해 유일하게)
- parallel/prep_rel 은 실제로 그 구조가 있을 때만 문자열, 없으면 null.
- JSON 유효성(필드명·따옴표).
